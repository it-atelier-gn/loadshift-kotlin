Sequential pipeline

Compiled for Camunda 7 and Camunda 8 and verified with 30 checks.

Tasks run one after another for every seeded item. Each task becomes an external service task.

Kotlin
workflow<Order>("billing-pipeline") {
    input(orders)
    task("validate") { it.attempts = 0 }
    task("charge") { charge(it) }
    task("receipt") { sendReceipt(it) }
}

Conditional branch

Compiled for Camunda 7 and Camunda 8 and verified with 32 checks.

condition/otherwise compiles to a decision service task plus an exclusive gateway pair.

Kotlin
workflow<Order>("order-triage") {
    input(orders)
    condition({ it.total > 100 }) {
        task("manual-review") { review(it) }
    } otherwise {
        task("auto-approve") { approve(it) }
    }
}

workflow<Order>("order-lines") {
    input(orders)

    fanOut(expand = { fetchLines(it.id) }, concurrency = 4) {

            task("bulk-price") { bulk(it) }
        } otherwise {
            task("unit-price") { unit(it) }
        }
    }
}

reduce folds the expanded children into one value and runs onComplete on the parent. It compiles to the fan-out plus a reduce service task after the last wave.

workflow<Order>("order-totals") {
    input(orders)
    fanOut(expand = { fetchLines(it.id) }, concurrency = 4) {
        task("price") { price(it) }
    }.reduce(0, combine = { sum, line -> sum + line.qty }) { order, units ->
        order.total = units
    }
}

Timed wait

Compiled for Camunda 7 and Camunda 8 and verified with 25 checks.

wait pauses the flow for a fixed duration. It compiles to an intermediate timer catch event the engine schedules natively.

Kotlin
workflow<Order>("retry-later") {
    input(orders)
    task("attempt") { charge(it) }
    wait(15.minutes)
    task("settle") { settle(it) }
}

Event with data or a deadline

Compiled for Camunda 7 and Camunda 8 and verified with 30 checks.

awaitMessage with a block applies the data sent along with the message to the item. With a timeout, an event-based gateway races the message against a timer; when the timer wins, the item runs the onTimeout steps. Both paths join before the next task.

Kotlin
workflow<Order>("await-or-remind") {
    input(orders)
    awaitMessage("payment-confirmed", timeout = 3.days) { order, data ->
        order.total = data.getValue("amount").jsonPrimitive.int
    } onTimeout {
        task("send-reminder") { remind(it) }
    }
    task("fulfil") { fulfil(it) }
}

catching attaches an error boundary event to the task. When the task throws the caught exception, the worker ends the job with a BPMN error and the item takes the branch without further attempts, then continues with the next task.

workflow<Order>("reserve-or-backorder") {
    input(orders)

    task("ship") { ship(it) }
}
