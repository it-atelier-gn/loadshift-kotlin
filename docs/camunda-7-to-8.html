One workflow, both engines

Camunda 7 and Camunda 8 use different BPMN extensions, different expression languages and different worker APIs. With loadshift the workflow is Kotlin code. The backend compiles it to the BPMN of its engine, deploys it, starts one process instance per item and works the external tasks or jobs with your task bodies.

Fulfilment.kt
val fulfilment = workflow<Order>("fulfilment") {
    input(openOrders)
    task("reserve") { reserve(it) }
        .catching<OutOfStock> { task("backorder") { backorder(it) } }
    awaitMessage("payment-confirmed", timeout = 3.days) { order, data ->
        order.paidAmount = data.getValue("amount").jsonPrimitive.double
    } onTimeout {
        task("send-reminder") { remind(it) }
    }
    task("ship") { ship(it) }
}

Camunda7Backend("http://camunda7:8080/engine-rest").run(fulfilment).await()

Camunda8Backend("http://camunda8:8080").run(fulfilment).await()

The same definition also runs in-process on LocalBackend, so tests of the workflow need no engine. examples.html shows the BPMN each example compiles to for both engines.

Switching over

Process instances stay on the engine that started them. Finish the Camunda 7 instances with a worker that takes them over, then seed on Camunda 8. When every run uses the same checkpoint store, including the Camunda 7 run that is still active, the Camunda 8 run skips every item that finished on Camunda 7.

Switchover.kt
val config = RunConfig(checkpoints = SqliteCheckpointStore("checkpoints.db"))

camunda7Handle.detach()
Camunda7Backend(camunda7Base).attach(fulfilment, config).await()

Camunda8Backend(camunda8Base).run(fulfilment, config).await()
STEPEFFECT
detach()The Camunda 7 run stops seeding and fetching, waits for running task bodies and leaves its instances on the engine
attach(workflow, config)Works the active Camunda 7 instances of the workflow until none are left and marks each finished item in the checkpoint store
run(workflow, config)Seeds on Camunda 8 and skips items the checkpoint store lists as complete

While attach runs, its handle delivers send and broadcast to the waiting Camunda 7 instances. Instances that wait for a message, a timer or a person keep the attach run open until they finish.

Versions on one engine

Within one engine, version(tag) tags every process of a workflow, and backend.migrate(workflow) deploys the workflow and moves the active instances of older definitions to it, matching elements by id. Instances that wait in an element the new version no longer has are reported with the engine's error.

Migrate.kt
val result = Camunda8Backend(camunda8Base).migrate(fulfilment)
println("migrated ${result.migrated}")
